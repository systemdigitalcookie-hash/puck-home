# Rules for AI coding tools working on this repo

This is firmware for a Waveshare ESP32-S3-Touch-LCD-1.85B (round 360x360 touch screen). The owner is a beginner. Be careful and explain what you change.

## What's in v3 (pink restyle of v2, same features)
- `theme.h`: the theme (colours, fonts, radii, dotted ring, drawing helpers). `art.h`: generated shapes.

## What's in v4 (same look as v3)
- Recorder: SD write/read-back self-test at boot (4-bit 20 MHz, then 1-bit 20/10/5 MHz), DMA-capable aligned write buffers, falls back to internal flash if the SD refuses the first write ("Saved to internal (SD error)"), SD status in Settings > Storage, cached file list and free space, SD writer on core 0.
- Speed: one SPI transfer per display strip, millis() LVGL tick, 16 KB loop stack, -O2 build, labels/dots only redrawn on change, no SD or battery work mid-swipe.

## What's in v5
- Start page is a full-screen plush face: cream background, round black eyes with white highlights, pink nose, small mouth, soft blush. No ears, no clock, no dotted ring and no page dots on that page. `theme_face()` in `theme.h` draws masks from `art.h` (generated by `tools/gen_art.py`).
- Swipe pages are now Recorder, Face, Clock, Settings (`NPAGES` is 4). The face is the start page. Check update stays on the Clock page and under Settings > About.

## What's in v6
- Screen button: the BOOT key (GPIO0) is the only button the code can read. `screen_btn.h` polls it from `loop()` (30 ms debounce).
  - Short press: screen off / on. Backlight to 0, panel display-off + sleep (`LCD_Power()` in `Display_ST77916.cpp`, sleep added to `esp_lcd_st77916.c`), and `Lvgl_Loop()` is skipped so there is no redraw and no touch. Recording, playback, Wi-Fi and OTA keep running.
  - Long press (0.8 s): closes the recording detail, Settings sub-screens and the Wi-Fi keyboard, clears a recorder error and goes to the Face page (stays on Recorder while recording). If the screen is off, a long press only turns it on.
  - GPIO0 is only read, never driven, so holding BOOT while plugging in still enters USB download mode. The other key (PWR) is wired to the power latch, not to a GPIO.

## Pages and files
- Swipe pages: **Recorder** (left), **Face** (start page), **Clock**, **Settings** (right).
- `recorder.cpp/.h`: microphone (ES7210) recording to WAV on the SD card (or internal flash), playback through the speaker (ES8311 + amp on GPIO9), save checks with exact error messages.
- `recorder_ui.h`: Recorder page. States are Ready, Recording, Paused, Saving, Saved and Error. It also has the recent recordings list and the detail screen (play/pause, progress, delete).
- `settings_ui.h`: Settings list with sub-screens: Sound, Microphone, Display, Storage, Wi-Fi, Battery and About (Check update).
- `wifi_net.h` + `wifi_ui.h`: the Wi-Fi picker. It scans in the background, takes a password on the on-screen keyboard and keeps up to 5 saved networks with Forget. At boot it joins the strongest saved network. The `Puck-Home-Setup` portal is only the fallback.
- `puck_home.ino`: OTA (`check_update`, `net_task`), RTC, battery gauge, the clock page, `build_ui()` and `loop()`.

## Rules
1. **Keep the OTA/Wi-Fi code intact.** `net_task`, `check_update`, `certs.h`, the `OTA_BASE`/`OTA_REPO` defines, `wifi_net.h` and the "Check update" buttons are how the puck gets updates without USB. If they break, the puck needs a USB cable again. You can add features around them. Don't remove or rewrite them.
2. **Always bump the version.** Never publish with an unchanged version, because the puck only updates when the remote `version.txt` is higher than its `FW_VERSION`. Change `puck_home/version.h` in the commit that should ship. Merging that to `main` publishes it (see Release below). `./release.sh` still bumps the number itself when you publish from a computer.
3. **Never commit secrets.** No Wi-Fi passwords, API keys, tokens or personal data in source, README or releases. Wi-Fi passwords live only in the puck's NVS, entered on the device. This repo is public.
4. **Keep the app under 3 MB** (partition `app3M_fat9M_16MB`). v2 is about 1.75 MB. `release.sh` fails the build if `firmware.bin` is too big. Avoid big images and fonts in flash.
5. **Don't change the partition scheme or FQBN** in `release.sh`. A different layout breaks OTA on devices already in use.
6. **Don't change the Wi-Fi AP name** `Puck-Home-Setup`.
7. Keep the soft pink, simple, cute style. **All colours, fonts, radii and the dotted ring settings are in `puck_home/theme.h`.** Change the look there, not in each page. Helpers (`ui_btn`, `ui_label`, `ui_title`, `ui_divider`) are in `ui_style.h`; cute shapes come from `theme_heart`, `theme_bow`, `theme_flower`, `theme_bunny_ears`, `theme_face` and `theme_bar`. The face page uses `C_CREAM`, `C_EYE`, `C_NOSE`, `C_MOUTH` and `C_BLUSH`.
   - Shapes are in `art.h`, GENERATED by `python3 tools/gen_art.py` (needs `pip install pillow`). They are 8-bit masks tinted by theme colours. Draw only original, generic doodles: no brand or character artwork, logos or names (this repo is public).
   - `python3 tools/mock_pink.py` draws an approximate preview PNG into `mock/` (gitignored).
8. Add new pages in `build_ui()` (one more `lv_tileview_add_tile`, raise `NPAGES` and the `dots[]` size) and refresh them from `loop()`. Leave the display, touch and LVGL drivers alone unless you really need to.
9. Don't call `Wire.begin()` again. `I2C_Init()` does it (SDA 11, SCL 10). Use I2C only from the main loop/UI task.
10. Never do slow work (network, file scans, `delay`) in LVGL callbacks. Post a request to the net task, like `wn_req_scan` does.

## Build only (check that it compiles, publishes nothing)
```
arduino-cli compile --fqbn "esp32:esp32:esp32s3:FlashSize=16M,PSRAM=opi,PartitionScheme=app3M_fat9M_16MB,CDCOnBoot=cdc,FlashMode=qio,USBMode=hwcdc" \
  --build-property "compiler.optimization_flags=-O2" \
  --libraries repo/examples/Arduino-V3.2.0/libraries --output-dir build puck_home
```
The first time, run `./release.sh` once or clone the Waveshare libraries into `repo/` (see `release.sh`). You need core `esp32:esp32@3.2.0` and the `WiFiManager` library.

## Release
GitHub Actions publishes, so a local `gh auth login` is not required. The workflow is `.github/workflows/release.yml`.

1. On a pull request it only builds (a dry run). It does not create a release. The job also runs `tools/release_gate_test.sh`, which checks the "is this version newer?" decision.
2. On a push to `main`, or a manual run from the Actions tab (`workflow_dispatch`), it installs arduino-cli 1.6.0, `esp32:esp32@3.2.0`, WiFiManager and the Waveshare libraries pinned in `release.sh`, then compiles with that file's FQBN and `-O2` flag.
3. It copies `firmware.bin`, `merged.bin` and `version.txt` the same way `release.sh` does, and fails if `firmware.bin` is 3 MB or bigger.
4. It creates GitHub release `vN` with those three files only when `FW_VERSION` is higher than the latest published release. The release is tagged at the commit that was built. `contents: write` on the release job is what allows `GITHUB_TOKEN` to publish. No extra secret is used.
5. If the build fails, the release job does not run, so nothing is published. The workflow does not bump `version.h`. Bump it before merging when the puck should update.
6. Check with `curl -sL https://github.com/<owner>/puck-home/releases/latest/download/version.txt`. It must print the new number.
7. The puck installs it on boot or when you tap Check update (Clock page, one swipe right from the face, or Settings > About).

`./release.sh` is still the local path. It bumps the version, builds, commits, pushes and publishes. It needs `gh auth login`. Do not change its FQBN or partition scheme. The Action reads that FQBN and refuses to build if it changes.
